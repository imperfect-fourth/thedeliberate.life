I use cloudflare tunnels and tailscale<sup id="anchor-0-src">\[[0](#anchor-0-dest)]</sup>
to get around my ISP's CGNAT. It's enough for the most part, but sometimes you
really need that static IP. 

When I torrent (totally legit material), I try to seed it for as long as I can.
But, I can't port-forward without a static IP, so the only peers I can connect
to are those who can port-forward. This is perfectly okay and would be enough
for most, but I'm big on giving back to the community so I want to reach all
the peers I can.


---

I started researching what I could do. My ISP does give me a global IPv6
address with a /64 subnet. If I can assign an IPv6 address on this subnet to a
docker container, my qbittorrent instance will become connectable for all
peers that support IPv6.

Docker has two network drivers for this: ipvlan<sup id="anchor-1-src">\[[1](#anchor-1-dest)]</sup>
and macvlan<sup id="anchor-2-src">\[[2](#anchor-2-dest)]</sup>. I
tried ipvlan first. I created a new IPv6-only docker network and attached it to
the qbittorrent instance.

```yaml
services:
  ...
  qbittorrent:
    ...
    networks:
      qb-ipvlan:
        ipv6_address: <subnet prefix>::1
networks:
  ...
  qb-ipvlan:
    driver: ipvlan
    enable_ipv6: true
    enable_ipv4: false
    driver_opts:
      parent: eno1
      ipvlan_mode: l2
    ipam:
      config:
        - subnet: <router's /64 subnet>
          gateway: <router IP>
```

This gave the container an IPv6 address on the subnet, but other containers on
a shared network couldn't reach the qbittorrent container anymore. The container also
published a port but it was no longer accessible on that port from any device
on my home network.

This is apparently a side-effect of how ipvlan works<sup id="anchor-3-src">\[[3](#anchor-3-dest)]</sup>.
It might be possible to make the ipvlan setup work, but when I was researching the
ipvlan issue, I found that macvlan might be more suited for my use-case. I
didn't get into the nitty-gritty differences between the two. That's saved for
another day. For now, I just went ahead with macvlan.


```yaml
services:
  ...
  qbittorrent:
    ...
    networks:
      ...
      qb-macvlan:
        ipv6_address: <subnet prefix>::1
networks:
  ...
  qb-macvlan:
    driver: macvlan
    ...
```

And this worked. qbittorrent container is now also announcing torrents on the
IPv6 address. It still doesn't solve connectivity for IPv4 peers, but I sleep a
little better at night now.
